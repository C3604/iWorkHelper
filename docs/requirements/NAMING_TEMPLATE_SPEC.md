# 命名模板规范 NAMING_TEMPLATE_SPEC

> 日期：2026-07-07（第八阶段：合并为单一命名规则）
> 实现：`Core/Archive/NamingTemplates.vb`、`NamingTemplateEngine.vb`、`ArchiveNamingRule.vb`；配置入口 `SettingsForm`。

## 1. 概述（分流后更新）

命名按**邮件/PDF 类型分流**（见 [MAIL_PDF_CLASSIFICATION_SPEC](MAIL_PDF_CLASSIFICATION_SPEC.md)）：

- **滴滴发票**：合并 PDF，用**滴滴命名模板**（默认 `{乘车日期}_{金额}_{出发地点}_{到达地点}`）。
- **常规发票**：每张单独归档，用**常规发票命名模板**（默认 `{开票日期}_{金额}_{销售方名称}`）。
- **未识别 PDF**：固定 `未识别_{原始文件名}.pdf`（内部规则，不作设置项）。

设置页面有**两个**命名规则输入框：滴滴发票、常规发票。变量说明区分两者适用变量。

## 2. 默认模板

```
{乘车日期}_{金额}_{出发地点}_{到达地点}
```

示例（脱敏假数据）：`20260518_138.46_上海虹桥站_上海市徐汇区.pdf`

## 3. 业务变量与取值优先级

| 变量 | 取值优先级 | 说明 |
|------|-----------|------|
| `{乘车日期}` | 行程出发日期 > 开票日期 | 规整为 YYYYMMDD |
| `{金额}` | 行程金额 > 价税合计 > 金额 | 业务通用金额 |
| `{出发地点}` | 行程起点 | 与 `{起点}` 同源 |
| `{到达地点}` | 行程终点 | 与 `{终点}` 同源 |

## 4. 支持的全部变量（单一来源）

**单一来源**：`ArchiveNamingRule.SupportedPlaceholders()`；设置页“变量说明”按钮、离线工具 `--help`、本文档四者一致。

- **业务常用**：`{乘车日期} {金额} {出发地点} {到达地点}`
- **通用**：`{邮件主题} {原附件名} {时间戳} {票据类型} {识别来源} {附件数量} {合并文件名}`
- **行程**：`{出发日期} {出发时间} {到达时间} {乘车人} {起点} {终点} {城市} {车型} {订单号} {里程} {行程金额}`
- **发票**：`{开票日期} {销售方名称} {购买方名称} {发票号码} {发票代码} {价税合计} {税额} {税率} {开票人} {项目名称}`

其中：`{出发地点}`=`{起点}`，`{到达地点}`=`{终点}`；`{识别来源}`=LocalText/BaiduOcr/Mixed/Failed；合并场景 `{原附件名}` 优先用邮件主题、否则首个 PDF 附件名；`{原始文件名}`=当前 PDF 附件原始名（常规/未识别用）。`{金额}` 常规发票=价税合计>金额。

### 常规发票默认模板
`{开票日期}_{金额}_{销售方名称}` → 例 `20260526_138.46_某某科技有限公司.pdf`。

## 5. 命名逻辑（优先级）

1. 使用用户配置的**统一模板**；用户配置为空 → 默认模板 `{乘车日期}_{金额}_{出发地点}_{到达地点}`。
2. 模板渲染后有效（非空、字段非严重不足）→ 使用渲染结果。
3. 渲染后为空/字段严重不足 → **fallback**：`未识别票据_{邮件主题}_{时间戳}`；邮件主题不可用 → `未识别票据_{原附件名}_{时间戳}`。
4. 空字段自动跳过；连续分隔符自动折叠（不产生多余下划线）。
5. Windows 非法字符自动清理（如 `| / : * ?` → `_`）。
6. 文件名过长自动截断（主体 ≤120 字符）。
7. 同名文件自动追加序号（`(1)(2)…`），不覆盖。
8. 未知变量记入警告（不导致归档失败）。
9. 命名结果记录：所用规则、缺失字段、未知占位符、**是否触发 fallback**（`ArchiveNamePlan` / `ArchiveItemResult`）。

## 6. 设置页面

- 只显示一个“命名规则”输入框（旧发票/行程单/未识别三行已隐藏）。
- **变量说明**按钮：展示上述全部变量（业务变量在前）。
- **预览**按钮：用脱敏假数据展示**一个**最终文件名预览（如 `20260518_138.46_上海虹桥站_上海市徐汇区.pdf`）；未知变量/ fallback 会提示；预览失败不影响保存。

## 7. 旧配置兼容

- 旧三套设置 `InvoiceNameTemplate` / `TripNameTemplate` / `UnknownNameTemplate` 仍保留在 `Settings.settings` 中（兼容），但**业务逻辑不再使用**，SettingsForm 不再展示。
- 新增 `UnifiedNameTemplate`（默认 `{乘车日期}_{金额}_{出发地点}_{到达地点}`）为唯一业务入口。
- 迁移：保存设置时若统一模板为空则写入默认模板；`NamingTemplates` 的 Invoice/Trip/Unknown 属性标记为 Obsolete，仅兼容。
