## 1. 端到端流程（需求 → 上线）
1. 需求分析
   - 输入：业务需求文档（包含滴滴发票/行程单识别与归档规则）。
   - 输出：用户故事、验收标准、范围与非功能需求（性能/安全）。
2. 架构与设计
   - 输出：模块划分、接口契约、数据模型、时序图与异常策略（见《开发框架与技术架构设计》）。
3. 实现开发
   - 约束：VB/.NET 4.8、VSTO 模板、遵循接口与依赖方向。
   - 要求：单元测试覆盖核心服务逻辑；避免在 UI 线程执行耗时操作。
4. 联调与测试
   - 内容：功能测试、兼容性测试（Outlook 365 2502/2016+）、性能测试（附件量级）。
   - 输出：测试报告与缺陷清单。
5. 发布与部署
   - 方式：ClickOnce 发布；证书签名；安装包分发。
   - 验证：目标机 Outlook 信任中心设置、加载项状态为「已加载」。
6. 监控与反馈
   - 内容：日志归档、异常统计、用户反馈收集与迭代计划。

## 2. 阶段交付物标准
- 需求阶段
  - 用户故事（Given/When/Then）与优先级标签（P0/P1/P2）。
  - 约束清单（例如：仅处理本地 PDF 附件，云链接需下载）。
- 设计阶段
  - 模块职责边界文档、接口定义、数据契约、流程时序。
  - 风险评估与备选方案（OCR 扫描版支持的可选性）。
- 实现阶段
  - 可编译项目、核心服务单元测试、示例配置（My.Settings）。
  - 代码注释与公共方法 XML 注释齐备。
- 测试阶段
  - 测试用例、覆盖率指标、性能基线（如 50 封邮件/100 个附件）。
- 发布阶段
  - ClickOnce 安装包、发布说明、安装与卸载指南。
- 运维阶段
  - 日志位置与滚动策略、故障处理 SOP、FAQ 文档。

## 3. 代码审查规范（Code Review）
- 必选规则
  - 启用 `Option Strict On` 与 `Option Explicit On`。
  - 禁止在 UI 事件中直接执行文件/网络等耗时操作（应使用异步任务）。
  - 公共方法需具备 XML 注释，说明输入/输出与异常。
  - 接口与实现分离；服务间依赖仅通过接口注入。
- 风格与命名
  - 类型/方法：PascalCase；局部变量：camelCase；常量：SNAKE_CASE。
  - 异常处理：仅在边界处捕获与翻译；业务层返回 `OperationResult`。
- 检查清单
  - 日志是否包含上下文 ID；是否有足够的 Warning/Error。
  - 是否处理了文件名冲突与不存在路径等边界情况。
  - 单元测试是否覆盖关键分支（成功/失败/异常）。

## 4. 版本控制策略（Git）
- 分支模型（GitFlow）
  - `main`：发布分支；仅合并 release/hotfix。
  - `develop`：开发分支；日常集成。
  - `feature/*`：特性分支（如 `feature/ribbon-ui`）。
  - `release/*`：预发布分支（如 `release/0.1.0`）。
  - `hotfix/*`：线上紧急修复。
- 提交信息规范
  - 格式：`<type>: <scope> - <subject>`，示例：`feat: mail - 支持滴滴发票识别`。
  - type：`feat` / `fix` / `docs` / `refactor` / `perf` / `test` / `build`。
- 标记与版本
  - 语义化版本：`MAJOR.MINOR.PATCH`（示例：`v0.1.0`）。
  - Tag：发布时在 `main` 打 Tag（如 `v0.1.0`），并同步更新《CHANGELOG》（见 [`Doc/CHANGELOG.md`](CHANGELOG.md)）。
- PR 流程
  - 至少 1 名审查者，优先 2 名；必须通过静态检查与单元测试。
  - 变更需关联用户故事或问题编号。

## 5. 测试策略
- 级别
  - 单元测试：服务层（Ocr/Merge/Rename/Archive）核心逻辑。
  - 集成测试：附件提取到归档的端到端流程（使用测试邮件与临时目录）。
  - 兼容测试：Outlook 2016/2019/365、不同 Windows 版本的加载与运行。
- 性能基线
  - 目标：同时处理 20 封邮件、总附件 50-100 个，平均单附件处理 ≤ 1.5s（文本型）。
- 日志与可观测性
  - 每次处理产生上下文 ID，关键阶段打点（提取、识别、合并、归档）。

## 6. 发布与部署
- ClickOnce 配置
  - 使用企业证书签名；启用自动更新检查（可选）。
  - 安装步骤与卸载方式需在发布说明中明确。
- 安装验证
  - `Outlook → 文件 → 选项 → 加载项` 确认 iWorkHelper 状态为「已加载」。
  - 如未加载，复核注册表的 `LoadBehavior = 3` 与证书信任设置。
